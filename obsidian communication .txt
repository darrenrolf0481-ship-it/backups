### Phase 3: Lock-Free Concurrency & Namespace Architecture


To prevent multiple active agents from crashing into each other (e.g., `zo.computer` writing a script while `Node::Hermes` summarizes notes), the communication protocol splits filesystem actions into **Hub & Spoke namespaces**:


```text
📁 /storage/emulated/0/Documents/Hermes/
├── 📁 00_Inbox/           ◄─ [Write-Ahead Logging] Ephemeral raw inputs & CLI scrapes
├── 📁 01_Projects/        ◄─ [Conversational Spokes] Active codebases & context files
│   └── 📁 project-name/
│       ├── 📄 _project-dna.md  ◄─ [SSOT Anchor] Structural constraints, ledger, thread index
│       └── 📁 threads/         ◄─ [Isolated Session Streams] Lock-free chronological writes
└── 📁 02_Agents/          ◄─ [Scratchpad Spoke] Private session logs per agent
```


*   **Conflict Bypass Strategy:** Agents do *not* write concurrently to a single master file. Instead, each session generates a unique, timestamped file in `01_Projects/[project-name]/threads/`.
*   **Context Token Budgeting:** To prevent context window blowouts, agents use a **"tree-ring memory"** system. They read only the relevant target threads and update the central **`_project-dna.md`** index note, collapsing historical noise into a high-density, easily queryable chronological ledger.

### Phase 4: Inter-Agent Thread Delegation (Bot Chat Protocol)


When a node needs to delegate a task to a specialized agent profile (like sending a request from `@architect` to `@coder`), it transitions the payload from raw markdown files into the **Hermes Bot Chat Protocol**:


```text
[Node::Architect]
       │
       ├─► Write Request Payload to Temp File (~/tmp/dm.txt)
       │
       ├─► Trigger Handoff via Hermes CLI:
       │   "hermes -p coder chat -c 'Bot Chat' --query-file ~/tmp/dm.txt"
       │
       ▼
[Node::Coder] ──► Reads Payload ──► Processes Task ──► Appends Attributed Markdown to threads/
```


1.  **Drafting the Handoff Payload:** The initiating agent writes its detailed task parameters directly to a temporary text file to bypass terminal truncation errors.
2.  **Queue Activation:** The agent triggers the background command execution using the `hermes` CLI pointing to the target recipient's specific profile (e.g., `-p coder`) and active conversation channel.
3.  **Result Integration:** The recipient agent wakes up, executes the payload, writes its processing logs into the project's shared vault directory, and posts an attributed, prefixed confirmation back to the orchestrating session.
